# Botの振る舞い

最終更新: 2026-10-27

## 決定事項

- **公開範囲:** 自分たちのサーバー専用にする。Developer Portalで「Public Bot」をOFFにし、サーバーに追加できるのは開発者だけにする。100サーバー以上で必要になるDiscordの審査は受けない。
- **AIへの指示(システムプロンプト):**
  - 全員共通の指示(Bobertの性格や口調)に加えて、各ユーザーが自分用の指示を設定できる。
  - 自分用の指示は`/prompt`で設定する。今の指示を入れた状態でモーダルを開き、編集してもらう。空にすると、指示なしに戻る。
  - 自分用の指示は1500文字まで。`/settings`で、ほかの設定と一緒に1通(2000文字)で全文を見せられる長さにする。
  - 全員共通の性格と口調は「フレンドリーで簡潔」。友達のように気軽な口調で、要点を短く答える。
  - 返答の言語は、話しかけられた言語に合わせる。
  - 返信のつながりに複数の人がいる場合は、返信した人の設定を使う。LLMの費用を払う人と同じ人になる。
- **返答の表示:** 完成してから一度に投稿する。生成中は「入力中…」を表示する。この表示は一定時間で消えるため、生成が終わるまで繰り返し送る。
- **長い返答:** 2000文字(Discordの1メッセージの上限)を超える場合は、段落やコードブロックの切れ目で複数のメッセージに分け、続けて投稿する。コードブロックの途中で分ける場合は、いったん閉じて次のメッセージで開き直す。2通目からは前のメッセージへの返信にして、返信のつながりから会話全体をたどれるようにする。
- **通知:** 返答は話しかけたメッセージへの返信として投稿し、話しかけた人にだけ通知する(2通目以降は通知しない)。AIの返答に含まれるメンションでは、誰にも通知しない。
- **エラー時の表示:**
  - メンションへの応答で起きたエラーは、返信で理由を短く表示する。例:「APIキーが無効です。登録し直してください」「残高が不足しています」。この返信はチャンネルの全員に見える。
  - スラッシュコマンドのエラーは、本人にしか見えない形で表示する。
- **画像:** メンション付きの投稿に添付された画像は、画像に対応したモデルならAIに渡す。テキストファイルなど画像以外の添付は読まない。`/feat`でOFFにできる(既定はON)。画像に対応していないモデルでは本文だけで答え、「このモデルは画像を読めません」と一言添える。
- **Web検索:** `/feat`で、ユーザーごとに使うかどうかを選べる。検索のたびに費用が増えるので、既定はOFF。
  - ONにした人の返答では、AIが必要と判断したときだけ検索する。1回の返答での検索は5回まで。
  - Anthropicで直接呼ぶClaudeは、AnthropicのWeb検索の道具を使う。Sonnet 5.5、Opus 5.5、Fable 5.1には、検索結果を絞り込む新しい版を、Haiku 5.5と「その他」のClaudeには古い版を使う。検索の地域は日本にする。検索に時間がかかって返答が途中で止まったら(`pause_turn`)、続きを頼む。
  - OpenRouter経由は、OpenRouterのWeb検索(`openrouter:web_search`)を使う。モデルが道具として呼ぶので、道具を使えないモデルでは検索できない。
  - 返答が引用したページを、出典として、返答の末尾に小さな文字で最大5件添える。例: `出典: [nikkei.com](<https://www.nikkei.com/…>)、[ja.wikipedia.org](<https://ja.wikipedia.org/…>)`。サイトのホスト名(`www.`は外す)をリンクにし、`<>`で囲んでリンクの埋め込みを出させない。
  - 検索できないモデルでは、検索せずに答え、「このモデルはWeb検索を使えません」と一言添える。
- **利用量の表示:** `/feat`でONにすると、返答ごとに使ったトークン数と概算の費用を表示する。既定はOFF。
  - 返答の末尾に、小さな文字の行(`-# `)で添える。例: `入力 12,345トークン(うちキャッシュ 10,000)・出力 678トークン・約$0.0021`。キャッシュから読んだ分がなければ、括弧の部分は書かない。
  - 費用は、OpenRouter経由なら、応答に含まれる費用を使う。Anthropicで直接呼ぶClaudeは、OpenRouterのモデル情報の単価(キャッシュの読み書きと、入力が多いときの単価を含む)から計算する。「その他」で入力したClaudeは単価が分からないので、トークン数だけを書く。
  - 入力が多いときの単価は、APIを1回呼ぶごとの入力のトークン数で決まる。道具やWeb検索で何回かに分けて呼んだときは、1回ごとに計算して足す。
- **サーバー管理者向けの設定:** 用意しない。Botが反応するチャンネルは、Discordのチャンネル権限で制御する。Botは、見る権限のないチャンネルでは反応しない。
- **利用規約とプライバシーポリシー:** 作らない。自分たちのサーバー専用のBotのため。

## スラッシュコマンド

名前は英語、説明は日本語にする。すべて、本人にしか見えない形で応答する。

| コマンド    | 内容                                                                       |
| ----------- | -------------------------------------------------------------------------- |
| `/setup`    | Anthropic APIキーの登録・OpenRouterへのログイン                            |
| `/model`    | 使うモデルの変更(セレクトメニュー)                                         |
| `/effort`   | AIの思考の深さ(effort)の変更。選べる段階や対応の有無はモデルによって異なる |
| `/feat`     | 機能のON/OFF(Web検索、利用量の表示、画像の読み取り)                        |
| `/prompt`   | 自分用のAIへの指示の設定                                                   |
| `/settings` | 現在の設定の確認                                                           |
| `/delete`   | 登録したキーや設定の削除                                                   |
| `/help`     | 使い方                                                                     |
- `/settings`の思考の深さは、使うモデルで実際に使う段階を書く(`low`を選べないモデルでは、代わりに使う段階)。自分用の指示は、先頭の50文字だけを書く。
- `/help`のコマンドの一覧は、登録するコマンドの説明から作る。コマンドを足せば、`/help`にも出る。

このほか、メッセージの右クリックメニュー(アプリ)に、次の2つを用意する。
- **「Bobertに聞く」:**
  - 選ぶと、質問を入力しなくても、AIがそのメッセージの意味を説明する。
  - 返答はチャンネルに投稿するので、返信して会話を続けられる。
  - 会話を続けるときに説明対象のメッセージも文脈に含められるよう、返答と説明対象のメッセージの対応を保存しておく。
- **会話の要約:**
  - 会話の中のメッセージで選ぶと、そのメッセージまでの会話を要約する。詳しくは[アーキテクチャ](architecture.md)「長い会話の自動要約」を参照。
  - 単価が上がるモデルで会話が長くなったときに出る案内の、「今すぐ要約」ボタンからも要約できる。
  - 項目の名前は、実装のときに決める。スラッシュコマンド(`/compact`)は、特定のメッセージを指して使えないので、作らない。
